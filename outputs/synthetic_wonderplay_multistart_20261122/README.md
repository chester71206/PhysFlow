# Synthetic WonderPlay exact-flow multi-start, 2026-11-22

This experiment uses the two automated-QA PASS scenes in `../synthetic_physics_batch_20261121/`: `baseball_drop` (GT E=15,000 Pa, ν=0.32) and `football_deflated_2s` (GT E=12,000 Pa, ν=0.32). The source dataset has 49 frames over 2 seconds and three Blender cameras. Parameter training here uses frames 0, 2, 4, 6, 8 (0–0.333 seconds), all three views at 128×128, with fixed initial MPM particles, gravity, ground collider, timestep, and camera masks. This window contains first contact and early rebound, but does not cover the full 2 seconds.

The training target `gaussian-exact` is generated by the unchanged WonderPlay Gaussian rasterizer from the saved native Warp MPM GT particle motion. Candidate motion uses the existing `RepairedTemporalRollout` Reverse AD path and the unchanged `WonderPlayFlowObjective`. The target covariances come from a GT rollout. Blender object masks restrict foreground. RAFT is not used. This is a self-consistency and optimization test, not a validation that Blender-visible mesh flow or real-video flow has its minimum at GT.

Each start stores `optimizer.pt` after every update, `history.csv`, `final.json`, and both plots. `gate.json`, `gt_gradient.json`, `local_sensitivity.json`, `exact_gt_targets.pt`, and gradient-gate JSON are stored at the scene-target directory. The runner resumes from a matching checkpoint and has an external timeout. Its learning rates halve at updates 50 and 75. The plotted per-update loss is measured **before** that update; `final.json` evaluates the final parameters after the last update.

## Reproduce

Run from the repository root with the PhysFlow Python environment. Pick a currently idle GPU; GPU 8/9 were idle for this run, while GPU 0–7 were occupied by another job. Use a new `--output` path if you need a fresh run instead of resume.

```bash
CUDA_VISIBLE_DEVICES=8 timeout 900s /disk2/ccchen/miniconda3/envs/physflow/bin/python \
  scripts/train_synthetic_wonderplay_multistart.py \
  --scene outputs/synthetic_physics_batch_20261121/scenes/baseball_drop \
  --output outputs/synthetic_wonderplay_multistart_20261122/baseball \
  --start-name highE_lowNu --start-E-ratio 1.35 --start-nu 0.27 \
  --max-frame 8 --frame-stride 2 --resolution 128 --checkpoint-interval 16 \
  --gradient-gate --epochs 100
```

For the second start, set `--start-name lowE_highNu --start-E-ratio 0.7 --start-nu 0.40`. Change `--scene` and `--output` to `football_deflated_2s` and `football` to reproduce the football runs. The reverse-AD gradient gate checks both parameter derivatives against centered differences **before** training; it is a check, not a finite-difference optimizer. The initial-start gate files in the output directories record the measured errors.

To evaluate the independent Blender visible-mesh flow at GT, add `--target-kind blender-mesh --gt-gradient --local-sensitivity --epochs 0` and use a separate output directory. The script prevents training on this target unless `--allow-nonzero-gt` is supplied because its GT loss is not close to zero. To regenerate tables and plots:

```bash
/disk2/ccchen/miniconda3/envs/physflow/bin/python scripts/report_synthetic_wonderplay_multistart.py
```

## Limits

The independent Blender target uses geometric visible-surface correspondence, composed across the selected frame intervals. WonderPlay renders Gaussian point flow, whose opacity, finite support, covariance, and visibility differ from Blender's mesh rasterization. The GT Blender-target loss is materially nonzero, so the successful four-start recovery under the Gaussian target does not establish parameter recovery from Blender RGB or optical flow. Neither scene models the real internal construction of a baseball or deflated football; E and ν are GT for the synthetic homogeneous elastic MPM model.
